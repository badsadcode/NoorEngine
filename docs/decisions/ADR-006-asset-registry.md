# ADR-006: Asset registry and identity

**Status:** Accepted
**Date:** 2026-11-15

## Context
Renaming or moving a file must not break scenes that use it (spec 8.2, M2 gate). Assets
generated by Noor tools already carry a stable id (Noor Interchange `id`), and regenerating them
must keep their identity.

## Options
- **A: Sidecar meta files** (`<file>.noormeta`) holding the GUID next to each source file
  (Unity's proven approach). Moves in the editor move both; Git sees both.
- **B: One central database file** mapping paths to GUIDs. Single point of corruption, merge
  conflicts on every import.
- **C: Path-based references.** Break on every rename.

## Decision
**A: one `.noormeta` per asset source file**, plus repair rules:
- An asset's **GUID** comes from its Noor Interchange manifest `id` when one sits next to it
  (`<name>.noor.json`); otherwise a new random UUID v4 is written on first import.
- The meta stores the GUID, the importer, the importer settings and the **SHA-256 of the source**.
- Scenes reference assets **only by GUID** (plus a sub-object name inside the asset where needed).
- **Moves outside the editor** (Explorer, Git): when a scan finds a source without a meta and an
  orphaned meta whose recorded SHA-256 matches, the meta follows the file. If several match, or
  none, nothing is guessed: the scan reports it.
- The registry is rebuilt by scanning `Assets/`; it is a cache, not a source of truth.

## Consequences
- Every importable file gets a small companion file in Git.
- Moving a file *and* changing its content outside the editor at the same time loses the link;
  the scan reports it as "missing" plus "new", for the user to repair.
