# ADR-008: .NET hosting for C# scripts

**Status:** Accepted · **Date:** 2026-11-15 · **Milestone:** 4

## Context
C# is a first-class gameplay language (spec 33.1). Scripts must run in the editor's play mode with
fast iteration (reload without restarting the editor, spec 7.4), in a standalone player, and be
debuggable from NoorCode later and from external IDEs now. NoorEditor itself is a .NET 10 process.

## Options
- **A. CoreCLR (.NET 10).** In the editor, scripts load into the editor's own runtime in a
  *collectible* `AssemblyLoadContext` (unloaded on Stop/recompile). In the player, the native exe
  hosts CoreCLR through `nethost`/`hostfxr` (`load_assembly_and_get_function_pointer`). One managed
  library, `NoorEngine.Scripting`, works in both.
- **B. Mono embedding.** Proven in Unity, but legacy relative to .NET 10 and a second runtime next
  to the editor's.
- **C. NativeAOT-compiled scripts.** Fast startup; no reload, no debugger attach in play mode.

## Decision
**A**, CoreCLR .NET 10:
- **Script projects** are ordinary SDK-style projects (`Scripts/Scripts.csproj`, generated by the
  editor) referencing `NoorEngine.Scripting`. They build with the .NET SDK (`dotnet build`), so
  Visual Studio, Rider and VS Code open the same project (spec 7.2), and NoorCode can use Roslyn
  language services later.
- **Scripts** derive from `NoorScript` (`OnStart`, `OnUpdate`, `OnFixedUpdate`, `OnLateUpdate`,
  `OnDestroy`) and are attached by a `script` component naming the class. They call the engine
  through the `noor_rt_*` C API (ADR-027) via P/Invoke; the runtime calls scripts through function
  pointers that `NoorEngine.Scripting` registers at start-up (`[UnmanagedCallersOnly]`), the same
  way in both hosts.
- **Reload**: the editor rebuilds and reloads the script assembly when Stop is pressed or scripts
  change while stopped. Reload while playing is not attempted in Milestone 4 (state would be lost
  silently).
- **Debugging**: attach any .NET debugger to NoorEditor (scripts run in-process). A NoorCode
  debugger (e.g. via netcoredbg, MIT) is later work.
- **Player builds** are framework-dependent in Milestone 4 (need the .NET 10 runtime installed;
  the player says so clearly if it is missing). Self-contained builds are an ADR-018 question.

## Consequences
- Developers need the .NET 10 SDK to compile C# scripts. Lua scripts need nothing extra.
- Script exceptions are caught per script and reported with the entity and stack trace; a failing
  script is disabled, the game keeps running.
- Licences: .NET runtime and SDK are MIT.
